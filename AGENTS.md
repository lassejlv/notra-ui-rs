# notra-ui-rs

A Rust port of [Notra UI](https://ui.usenotra.com) (123 shadcn registry items) for
two renderers: GPUI (`--features gpui`) and Rune (`--features rune`). The goal is a
1:1 match of the live site: colours, metrics, shadows, typography and motion.

## Layout

- `src/theme.rs`: tokens extracted from the site's CSS (light and dark), `Color`
  (sRGB, straight alpha, `mix` = CSS `color-mix(in oklab)`), `Shadow`, radii.
- `src/motion.rs`: CSS curves (`ease::OUT` etc.), `Tween`, `Loop`, `keyframes`,
  `Animated` (a CSS transition for immediate-mode renderers).
- `src/icons.rs`: GENERATED by `node scripts/gen-icons.mjs` from `assets/icons/*.svg`.
  Add an SVG (24 view box, `currentColor` paint) and rerun; never edit by hand.
- `src/fonts.rs`: bundled OFL faces (Inter, Geist Mono, Instrument Serif).
- `src/components/<family>.rs`: framework-agnostic models: variants, metrics measured
  on the site, resolved skins per `Theme`, state machines, motion timings, demo data.
  Both renderers read these, so a value lives in exactly one place.
- `src/gpui/<family>.rs`: GPUI rendering. Stateless parts are `RenderOnce`
  (`#[derive(IntoElement)]`); per-element motion state uses
  `window.use_keyed_state(id, cx, ..)` and `window.request_animation_frame()` while
  animating (see `src/gpui/button.rs`). Colours convert with `.into()` from
  `theme::Color`; gradients with `gpui::gradient`, shadows with `gpui::shadows`.
- `src/rune/<family>.rs`: Rune rendering as builders ending in `.build(&theme) -> El`,
  handlers generic over app state (`on_press<S>`), colours via `ToRune::rune()`,
  CSS transitions via `rune::tween`, loops via `LoopSpec`, presence via `Transition`
  (see `src/rune/button.rs`). State a component needs (open menus, selection) lives in
  a small `*State` struct the app owns and passes in.
- `examples/gpui_gallery/` and `examples/rune_gallery/`: one page module per family,
  registered in each `main.rs` (`pages()` / `PAGES` and Rune `scenes`).

The `gpui` and `rune` features are mutually exclusive in one build (their fontconfig
features clash); `lib.rs` enforces it.

## Pins

- GPUI: zed `7733b9922665f103abda7c6a3fde6b9dfdc8eba9` (Linux needs gpui's `x11`/`wayland`
  features, set in Cargo.toml).
- Rune: `65f8eb43f710e078f92cb82039212de50cb03113`, with Rune's `[patch.crates-io]` table.
  Apps depending on this crate with `rune` must repeat that patch table.
- Toolchain 1.99.1 (`rust-toolchain.toml`).
- Cargo must fetch git with the CLI on Capy machines:
  `printf '[net]\ngit-fetch-with-cli = true\n' >> ~/.cargo/config.toml`.

## Reference material

The live site is the source of truth; the registry gives the React source.

- Registry: `https://ui.usenotra.com/r/registry.json`, items at
  `https://ui.usenotra.com/r/<name>.json` (`files[].content` is the TSX, `css`/`cssVars`
  hold keyframes and tokens).
- Live previews are iframes at `/blume-examples/<component>/examples/<example>`; the
  docs page `/components/<name>` or `/blocks/<name>` lists them.
- `scripts/probe-notra.mjs` (needs `npm i playwright-core` and Chrome) dumps computed
  styles, element screenshots and animation frame strips from those iframes, light or
  `--dark` (dark uses `prefers-color-scheme`; never toggle classes, the page hangs).

## Checks

```sh
cargo fmt --check
cargo test
cargo clippy --features gpui --all-targets -- -D warnings
cargo clippy --features rune --all-targets -- -D warnings
cargo build --features gpui --example gpui_gallery
cargo build --features rune --example rune_gallery
./target/debug/examples/rune_gallery --snap out/<scene>.png --scene <scene> --scale 2
```

GPUI renders on X11 (`DISPLAY=:9` on Capy machines); capture with
`import -window root out.png` after launching `gpui_gallery --page <slug> [--dark]`.
Compare every page against the probe's screenshots of the live examples, light and dark.
